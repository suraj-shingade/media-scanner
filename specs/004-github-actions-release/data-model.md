# Data Model: Automated Release Delivery Pipeline

**Feature**: 004-github-actions-release | **Date**: 2026-06-04

This feature introduces no application data model changes. The entities below describe the pipeline's conceptual model — inputs, intermediates, and outputs — as they flow through the GitHub Actions workflow.

---

## Entities

### Version Tag

The triggering input for the release pipeline.

| Attribute | Description | Example |
|-----------|-------------|---------|
| `name` | Full tag name including `v` prefix | `v1.2.3` |
| `version` | Semver string (tag name with `v` stripped) | `1.2.3` |
| `commit_sha` | The commit the tag points to | `abc123f...` |
| `pattern` | Required format: `v<major>.<minor>.<patch>` | `v[0-9]+.[0-9]+.[0-9]+` |

**Rules**:
- Tags not matching the pattern do not trigger the workflow (enforced by the trigger filter).
- The `version` string is used as the Maven project version, jpackage `--app-version`, and GitHub Release tag.

---

### Platform Build

One execution of a platform-specific build job. Two instances exist per pipeline run: one for macOS and one for Windows.

| Attribute | Description |
|-----------|-------------|
| `platform` | `macos` or `windows` |
| `runner` | `macos-latest` or `windows-latest` |
| `jdk_distribution` | `zulu` (macOS) or `temurin` (Windows) |
| `maven_profile` | `package-mac` or `package-win` |
| `status` | `success` or `failure` |
| `artifact_name` | Name of the produced installer file |

**State transitions**:
```
queued → running → success
                 → failure
```

**Rule**: If either Platform Build reaches `failure`, the Publish Release job does not execute (FR-008).

---

### Release Artifact

A platform-specific installer file produced by a Platform Build and ultimately attached to the GitHub Release.

| Attribute | Description | Example |
|-----------|-------------|---------|
| `filename` | Installer file name | `MediaScanner-1.2.3.dmg` |
| `platform` | Target OS | `macos` or `windows` |
| `format` | Installer format | `dmg` or `msi` |
| `version` | Embedded app version | `1.2.3` |
| `size_bytes` | File size | — |
| `sha256_hash` | SHA-256 digest of the file | 64-character hex string |

---

### Checksum File

A text file containing the SHA-256 hash of a Release Artifact, published alongside it for download integrity verification (FR-014).

| Attribute | Description | Example |
|-----------|-------------|---------|
| `filename` | Checksum file name | `MediaScanner-1.2.3.dmg.sha256` |
| `content` | `<sha256_hash>  <artifact_filename>` | `abc123...  MediaScanner-1.2.3.dmg` |
| `format` | Two-space-separated hash + filename (shasum-compatible) | — |

---

### GitHub Release

The published release entry on the repository's Releases page.

| Attribute | Description | Example |
|-----------|-------------|---------|
| `tag` | Git tag name | `v1.2.3` |
| `title` | Release display title | `MediaScanner 1.2.3` |
| `notes` | Release notes body | Auto-generated by GitHub |
| `status` | `published` (immediately upon creation) | — |
| `attachments` | List of attached files | 4 files: 2 installers + 2 checksums |
| `is_latest` | Whether marked as the latest release | `true` |

**Rule**: A GitHub Release is always published immediately — never as a draft (clarification Q1). If a release for the same tag already exists, it is deleted before the new one is created (clarification Q2, FR-013).

---

### Pipeline Run

A single end-to-end execution of the release workflow, initiated by one Version Tag push.

| Attribute | Description |
|-----------|-------------|
| `trigger_tag` | The Version Tag that initiated this run |
| `mac_build` | Associated macOS Platform Build |
| `win_build` | Associated Windows Platform Build |
| `release` | The GitHub Release produced (if successful) |
| `outcome` | `published`, `failed`, or `skipped` |
| `duration_minutes` | Total wall-clock time from trigger to publish |

**Rule**: `outcome = published` only when both `mac_build.status = success` AND `win_build.status = success`.  
**Constraint**: `duration_minutes ≤ 30` under normal conditions (FR-010, SC-001).
